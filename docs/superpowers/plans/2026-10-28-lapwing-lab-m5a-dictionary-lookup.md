# Lapwing Lab M5a: Dictionary Lookup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lookup searches the whole official Lapwing dictionary and shows every outline of a word, shortest first, with the book's chapter labels where the book teaches an outline and nothing the data does not say.

**Architecture:** The official dictionary files are vendored read-only into `content/lapwing-dictionary/`. The content build merges them with the book's labels (practice lists, briefs, examples, generated drills) into one `content/build/dictionary.json` (cards with ordered outline rows, labels, tags, book-only rows). The client fetches that file lazily on the first Lookup open and searches it with a pure module; the Lookup drawer UI is rewritten on top of it. The M4 `lookup.json` pipeline is retired.

**Tech Stack:** Node 26 (`node:*` only in scripts/server), Vite + Preact 11 + TypeScript, Vitest + Testing Library (jsdom). Branch `m5a-dictionary` (already created from `main` at `0e50b99`; the design commit is `7e7fada`).

**Spec:** `docs/superpowers/specs/2026-10-28-lapwing-lab-m5a-dictionary-lookup-design.md` (rulings C1–C18 in §7 and §7a bind this plan). Amends `docs/superpowers/specs/2026-10-27-lapwing-lab-design.md`.

## Global Constraints

- Offline, local, private repo. The running app makes no network request except to its own `127.0.0.1` server. `data/` (the owner's real archive, git-ignored) is never read or written by this feature, by tests, or by agents.
- Only the official Lapwing dictionary files are used; the owner's own Plover dictionaries are never read or merged.
- Lookup lists every outline; no chapter limit and no `Include later chapters` checkbox in Lookup (the Briefs tool keeps its own). The only label is the book's (`Chapter N` + kind) and the exact source-file tags. No heuristic classification.
- Client code imports from `scripts/` and `server/` with `import type` only; no `node:*` in the client bundle.
- Code style: no semicolons, single quotes, 2-space indent, `.ts`/`.tsx` import suffixes, colours only from the `:root` tokens in `src/ui/reader.css`, calm dark UI, no emoji. No new dependencies.
- Preact 11 defers `useEffect` cleanup: guard async state with live flags and use `useLayoutEffect` where cleanup must be synchronous.
- Every task leaves `npm test`, `npm run typecheck` and `npm run build` green.
- Vendored pinned commit of the dictionary: `4ac5d53cf039a2b1f4c484456663c85e7df4e859` of `https://github.com/aerickt/plover-lapwing-aio` (MIT). Files, all from `plover_lapwing/dictionaries/`: `lapwing-base.json`, `lapwing-uk-additions.json`, `lapwing-proper-nouns.json`, `lapwing-numbers.json`, `lapwing-commands.json`, `lapwing-semi-modal-movement.json`.
- Measured on those files (use as sanity bounds in tests): about 144,000 outline entries, about 58,000 distinct translations (exact strings), 36,000 with more than one outline, 13 outlines with different translations across files. `especially` writes `EPS`, `ES/PERB/HREU`, `ES/PERBL/KWREU`; `the` writes `-T`; `cat` writes `KAT`; `mistake` writes `SPHAEUBG` and `PHEUS/TAEUBG`.

## Review Focus

1. A one-letter or very common query (`a`, `s`, `the`) matches tens of thousands of cards: the search must stay responsive (a measured ceiling in a test), only 30 cards render at a time, the count line shows the total, and `Show more` adds 30.
2. Odd translations: the main file contains entries with newlines or tabs (for example `{^\n^}` and a metadata line starting `Date: 2025-11-05` followed by a tab) and Plover syntax (`{^}.sh`, `{#Shift_l(Home)}`). They are shown exactly as stored but with control characters made visible (`\n`, `\t`), in monospace, as plain text (no HTML injection).
3. Case variants and near-duplicates (`I`/`i`, `defense`/`Defense`): separate cards; an exact-case match sorts first among equals; case-insensitive matching.
4. Outline queries: partial outlines, `#` and `*`, `/` boundaries (`TK` matches `TKAT` and `-T/TKAT`, not `-T/KAT`), a lone `/`, a leading or trailing `/`, and lower-case steno-looking text (`tkad` is a word search only).
5. A corrupt, empty or partial `dictionary.json`, a failed fetch, a query typed while the file is still loading (the search runs when it arrives), and a retry; plus the vendoring script refusing anything but a full 40-hex commit and never being run by tests.

### Task 3: Build the cards with the book's labels

**Files:**
- Modify: `scripts/lib/dictionary.ts`, `tests/scripts/dictionary.test.ts`

**Interfaces:**
- Consumes: Task 2's types and helpers; `PracticeItem` (`{ prompt: string; outlines: string[] }`) from `scripts/lib/practice.ts`; `BriefRow` from `scripts/lib/tables.ts`; `ExampleRow` from `scripts/lib/examples.ts` (`{ chapter, word, outlines }`); `LookupList` (`{ id; chapter; items: PracticeItem[] }`) from `scripts/lib/lookup.ts` (the type stays until Task 7 moves it).
- Produces: `buildDictionary(input: { files: Record<DictFile, Record<string, string>>; lists: LookupList[]; briefs: BriefRow[]; examples: ExampleRow[]; commit: string }): DictionaryFile`.

Rules (spec §4, C10–C13, C17; the implementer writes the algorithm):
- One card per exact translation string. Its rows are every outline of that string, each with `f` listing every non-main file that holds the pair (omitted when only `main` holds it), sorted by `compareOutlines`. Cards sort by lower-cased text then exact text.
- A book entry is a (text, outline, chapter, source, optional note) from: every item of every list (`prompt` text, `source: 'practice'`), every brief row (`translation`, one entry per outline, `source: 'brief'`, `note` = the row's `explanation` when not empty), every example row (`word`, `source: 'example'`). The lists passed in include the generated drill lists (Task 4 supplies them).
- Join: a book entry attaches as a `b` label to a row when the outline is equal and the entry's text equals the card's `t` after trimming and ignoring case. The same (outline, chapter) from several sources is one label per source; keep the first non-empty note per (outline, chapter, source). Label order: chapter, then practice, brief, example.
- If the entry's text matches one or more cards (ignoring case) but none has that outline: add a `x: true` row (with the label) to the card whose `t` equals the entry's text exactly, else to the first matching card; rows stay in order.
- If the entry's text matches no card at all (a name such as `Enter or Return`, `Comma (,)`, `a^`, or a word the dictionary lacks): the text gets its own card with `n: true`, one row per distinct outline carrying the labels and `w` = every translation the dictionary has for that outline (sorted, possibly empty); the first such text seen keeps its display form; texts merge by trimmed lower-case.
- `letters`: filled from the list with id `18-lowercase` when present in `lists` (item `prompt` letter → first outline), else `{}`.

Then one guard on the real vendored files with fixture lists only: `especially` card rows are exactly `EPS`, `ES/PERB/HREU`, `ES/PERBL/KWREU` in that order.

### Task 5: Search the dictionary in the client

**Files:**
- Create: `src/core/dictsearch.ts`, `tests/core/dictsearch.test.ts`

**Interfaces:**
- Consumes: type-only `DictCard`, `DictRow` from `../../scripts/lib/dictionary.ts`; `compareOutlines` from `./outline.ts`.
- Produces (exports of `src/core/dictsearch.ts`, pure: no DOM, no fetch, no Node):
  - `looksLikeSteno(query: string): boolean` (the same rule as today: `/^[#STKPWHRAO*EUFRPBLGTSDZ\-/]+$/` on the trimmed query).
  - `type DictMatch = 'exact' | 'prefix' | 'contains' | 'outline-exact' | 'outline-prefix' | 'outline-contains'`.
  - `type DictResult = { card: DictCard; match: DictMatch; hit?: ReadonlySet<string> }` (`hit`: the outlines that matched, for outline matches only).
  - `searchDictionary(cards: readonly DictCard[], query: string): DictResult[]`: the whole ordered list (the caller shows 30 at a time). Per-array precomputation (lower-cased texts) is cached in a module `WeakMap` keyed by the `cards` array.
  - `visibleText(text: string): string`: replaces `\n`, `\r` and `\t` with the two-character escapes `\n`, `\r`, `\t`; every other character unchanged.
  - `fingerspell(query: string, letters: Readonly<Record<string, string>>): string[] | null`: for a query that is one run of lower-case letters `a-z` (after trimming), the outlines of its letters in order; `null` otherwise or when a letter is missing from `letters`.

Search rules (spec §4, C14, C15):
- Empty or whitespace-only query: `[]`.
- Word search (every query): compare lower-cased trimmed query with each card's lower-cased text. Groups: exact (equal), then prefix, then contains. Inside a group: cards whose text equals the query exactly (same case) first, then shorter text first, then alphabetical by lower-cased text, then exact text.
- Outline search (only when `looksLikeSteno`): runs first. A card matches when any row's outline equals the query (group `outline-exact`), else starts with it (`outline-prefix`), else has a `/` boundary after which the remainder starts with it (`outline-contains`; a match inside a stroke that is not at a stroke start does not count). `hit` is every row of the card that satisfies the card's group criterion (equal for exact, starts-with for prefix, boundary-start for contains). Inside a group: by the best matching row (`compareOutlines` from `./outline.ts`: fewest strokes, then keys, then alphabetical), then by card text. Word results follow, skipping cards already listed.
- A named card (`n`) takes part in word search by its text and in outline search by its rows.

Behavior (spec §4; exact texts):
- Loading: `fetch('/content/dictionary.json')` once, module-level cache of the successful promise (failure not cached; a late settle after the reset must not leak: assign the `loaded` mirror only when `cache === request`); a `loaded` mirror so a reopened drawer has no loading flash; live-flag guarded state. The input is always rendered; while loading the status line says `Loading…` and a query typed meanwhile is searched when the data arrives. - Empty/whitespace query: `Start typing to look something up.` Results: a count line `N results` (`1 result`) with `aria-live="polite"` on the count/empty/status lines only, then cards.
- Cards: 30 shown, a `Show more` button adds 30 (hidden when everything is shown); typing a new query resets to 30. Card heading: the translation through `visibleText`, in monospace when it contains a character outside letters, digits, spaces and basic punctuation or starts with `{`; otherwise normal text. A named card (`n`) shows a muted `from the book` marker next to its heading.
- Rows: stroke chips (`code.stroke[tabindex=0][data-stroke]`, `/` separators; hover or focus sets the preview board, which keeps the last chip and defaults to the first stroke of the first row of the first card, hidden with no results; reuse the M4 sticky preview rules); then, in this order, the book's labels (`Chapter N`, kinds joined as `practice list, brief, example`, the note), the source tags (`uk`→`UK`, `names`→`names`, `numbers`→`numbers`, `commands`→`commands`, `movement`→`movement`), `book only` for `x` rows. Outline-search results emphasise the rows in `hit` (a class, not just colour). For named cards each row adds a muted line `The dictionary writes this outline as:` followed by the `w` translations through `visibleText`, or `not in the dictionary` when `w` is empty.
- Not found (word-like or steno-like query with no results): `Not in the dictionary.`; when `fingerspell` returns outlines, a muted line `Fingerspell it:` with those outlines as chips (also set the preview).
- No chapter limit, no checkbox, no use of `useProgress` in Lookup.
